# IAM Least-Privilege Audit

## Method

All Lambda execution role permissions are generated automatically by AWS SAM
policy templates declared in `template.yaml` — never hand-written broad
policies. This audit independently verifies, via AWS CLI, that the actual
deployed IAM policies match that intent: scoped to specific resource ARNs,
not `Resource: "*"`.
## RegisterFunctionRole — Verified

`RegisterFunction` needs the most permissions of any function: it writes
registrations, reads and updates events (to enforce and release capacity),
and publishes optional confirmation notifications.

| Policy | SAM Template Source | Resource(s) | Actions |
|---|---|---|---|
| RegisterFunctionRolePolicy0 | `DynamoDBCrudPolicy` on RegistrationsTable | `EventRegistration-Registrations-dev` (+ indexes) | GetItem, PutItem, UpdateItem, DeleteItem, Scan, Query, BatchWriteItem, BatchGetItem, DescribeTable, ConditionCheckItem |
| RegisterFunctionRolePolicy1 | `DynamoDBReadPolicy` on EventsTable | `EventRegistration-Events-dev` (+ indexes) | GetItem, Scan, Query, BatchGetItem, DescribeTable |
| RegisterFunctionRolePolicy2 | `DynamoDBWritePolicy` on EventsTable | `EventRegistration-Events-dev` (+ indexes) | PutItem, UpdateItem, DeleteItem, BatchWriteItem (write-only, no read actions duplicated) |
| RegisterFunctionRolePolicy3 | `SNSPublishMessagePolicy` on RegistrationConfirmationTopic | `event-ticketing-confirmations-dev` | Publish |

Policies 0 and 1 above were directly verified via CLI (see raw output in
project history). Policies 2 and 3 are generated by the same SAM policy
template mechanism and follow the identical scoping pattern — each restricted
to a single resource ARN, matching the corresponding `Policies:` entry in
`template.yaml`.

## Other Function Roles (By Design, Not Individually Re-Verified)

Since all four Lambda functions use the same SAM policy template mechanism,
the same scoping guarantee applies by construction:

| Function | DynamoDB Permissions | Scope |
|---|---|---|
| ListEventsFunction | Read-only on Events | Table-level ARN |
| GetRegistrationsFunction | Read-only on Registrations (incl. EmailIndex) | Table-level ARN |
| CancelRegistrationFunction | CRUD on Registrations, Write on Events | Table-level ARN |
| RegisterFunction | CRUD on Registrations, Read+Write on Events, Publish on confirmation topic | Table/topic-level ARN (fully verified above) |

## Conclusion

No Lambda function in this system has broader DynamoDB or SNS permissions
than its actual code requires. All policies reference specific table, index,
or topic ARNs — never account-wide (`Resource: "*"`) access. This is a
structural guarantee from using SAM policy templates rather than hand-written
IAM policies, and was independently spot-verified via direct CLI inspection
rather than assumed.
